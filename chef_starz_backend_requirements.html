2. Authentication & Authorization

2.1 User Registration

POST /auth/signup or /auth/register

Request Body:

{
  "name": "string (required)",
  "email": "string (required, valid email format)",
  "password": "string (required, min 8 characters)",
  "parentEmail": "string (optional, for child accounts)"
}

Success Response (201):

{
  "success": true,
  "data": {
    "user": {
      "id": "string",
      "name": "string",
      "email": "string",
      "parentEmail": "string | null",
      "isVerified": false,
      "avatar": "string | null",
      "bio": "string | null",
      "location": "string | null"
    },
    "accessToken": "string (JWT)",
    "refreshToken": "string (JWT)",
    "requiresParentApproval": "boolean"
  }
}

2.2 Email Verification

POST /auth/verify-email

Request Body:

{
  "email": "string",
  "code": "string (6-digit verification code)"
}
POST /auth/resend-verification

Request Body:

{
  "email": "string"
}

Success Response (200):

{
  "success": true,
  "data": {
    "message": "Verification code sent",
    "cooldownSeconds": 60
  }
}

2.3 Login

POST /auth/login

Request Body:

{
  "email": "string",
  "password": "string"
}

2.4 Social Login

POST /auth/google

Request Body:

{
  "idToken": "string (from Google Sign-In SDK)"
}
POST /auth/apple

Request Body:

{
  "identityToken": "string (from Apple Sign-In)",
  "authorizationCode": "string"
}

2.5 Password Reset

POST /auth/forgot-password

Request Body:

{
  "email": "string"
}
POST /auth/reset-password

Request Body:

{
  "email": "string",
  "code": "string (verification code)",
  "newPassword": "string"
}

2.6 Token Management

POST /auth/refresh-token

Request Body:

{
  "refreshToken": "string"
}

Success Response (200):

{
  "success": true,
  "data": {
    "accessToken": "string",
    "refreshToken": "string"
  }
}
POST /auth/logout

Headers: Authorization: Bearer <token>

2.7 Parent Approval Status

GET /auth/approval-status/:userId

Headers: Authorization: Bearer <token>

Success Response (200):

{
  "success": true,
  "data": {
    "isVerified": "boolean",
    "approvalStatus": "pending | approved | rejected"
  }
}

Token Specifications Required

  • Token Type: JWT
  • Header Format: Authorization: Bearer <accessToken>
  • Access Token TTL: Specify duration (e.g., 1 hour)
  • Refresh Token TTL: Specify duration (e.g., 30 days)
  • Token Refresh Flow: Auto-refresh on 401 or manual refresh

3. User Profile Management

3.1 Get User Profile

GET /users/:userId or /users/me

Headers: Authorization: Bearer <token>

Success Response (200):

{
  "success": true,
  "data": {
    "id": "string",
    "name": "string",
    "email": "string",
    "parentEmail": "string | null",
    "isVerified": "boolean",
    "bio": "string | null",
    "avatar": "string (URL) | null",
    "location": "string | null",
    "followersCount": "number",
    "followingCount": "number",
    "recipesCount": "number",
    "createdAt": "ISO 8601 timestamp"
  }
}

3.2 Update User Profile

PUT/PATCH /users/me

Request Body:

{
  "name": "string (optional)",
  "bio": "string (optional)",
  "location": "string (optional)",
  "avatar": "string URL (optional, after upload)"
}

3.3 Upload Profile Picture

POST /users/me/avatar

Headers:

  • Authorization: Bearer <token>
  • Content-Type: multipart/form-data

Request Body: avatar (file)

4. Recipe Management

4.1 Get Recipes (List with Pagination)

GET /recipes

Query Parameters:

  • page (number, default: 1)
  • limit (number, default: 20, max: 50)
  • sort (string: latest, popular, rating)
  • category (string, optional)

Success Response (200):

{
  "success": true,
  "data": [
    {
      "id": "string",
      "title": "string",
      "chefName": "string",
      "chefId": "string",
      "chefAvatar": "string (URL)",
      "time": "string (e.g., '30 min')",
      "servings": "string (e.g., '4 servings')",
      "description": "string",
      "image": "string (URL)",
      "rating": "string (e.g., '4.5')",
      "likesCount": "number",
      "commentsCount": "number",
      "isLiked": "boolean",
      "isSaved": "boolean",
      "createdAt": "ISO 8601 timestamp"
    }
  ],
  "pagination": {
    "currentPage": 1,
    "totalPages": 10,
    "totalItems": 200,
    "perPage": 20,
    "hasNext": true,
    "hasPrevious": false
  }
}

4.2 Get Recipe Details

GET /recipes/:recipeId

Response includes: All list fields plus ingredients, frostingIngredients, and steps array

4.3 Create Recipe

POST /recipes

Request Body:

{
  "title": "string (required)",
  "description": "string (required)",
  "time": "string (required)",
  "servings": "string (required)",
  "image": "string URL (required, after upload)",
  "ingredients": ["string"],
  "frostingIngredients": ["string"] /* optional */,
  "steps": [
    {
      "title": "string",
      "description": "string",
      "image": "string (URL)"
    }
  ]
}

4.4 Update Recipe

PUT/PATCH /recipes/:recipeId

4.5 Delete Recipe

DELETE /recipes/:recipeId

4.6 Get User's Recipes

GET /users/:userId/recipes

9. File Upload

9.1 Image Upload

POST /upload/image

Headers:

  • Authorization: Bearer <token>
  • Content-Type: multipart/form-data

Request Body: image (file)

File Constraints

  • Max file size: 10MB (confirm with backend)
  • Allowed formats: JPEG, PNG, WebP
  • Min dimensions: 800x600px (confirm)
  • Max dimensions: 4000x4000px (confirm)

Success Response (200):

{
  "success": true,
  "data": {
    "imageUrl": "string (full URL)",
    "thumbnailUrl": "string (optional)",
    "width": "number",
    "height": "number"
  }
}

9.2 Video Upload (if applicable)

POST /upload/video

File Constraints

  • Max file size: 50MB (confirm)
  • Max duration: 60 seconds (confirm)
  • Allowed formats: MP4, MOV

9.3 Alternative: Pre-Signed URL Upload

GET /upload/presigned-url

Query Parameters: fileType, fileName

POST /upload/confirm

Request Body: fileKey

11. Error Response Structure

Standard Error Format

{
  "success": false,
  "error": {
    "code": "string (e.g., 'AUTH_001', 'VALIDATION_ERROR')",
    "message": "string (user-friendly message)",
    "details": [
      {
        "field": "email",
        "message": "Invalid email format",
        "code": "INVALID_FORMAT"
      }
    ],
    "timestamp": "ISO 8601 timestamp"
  }
}

HTTP Status Codes

Code Meaning Usage
200 OK Successful GET, PUT, PATCH
201 Created Successful POST (resource created)
204 No Content Successful DELETE
400 Bad Request Validation errors, malformed request
401 Unauthorized Missing/invalid/expired token
403 Forbidden Insufficient permissions
404 Not Found Resource doesn't exist
409 Conflict Duplicate resource
422 Unprocessable Entity Semantic errors
429 Too Many Requests Rate limit exceeded
500 Internal Server Error Server error
503 Service Unavailable Server maintenance
Note: Request a complete error code taxonomy from the backend team with all possible error codes and their descriptions.

12. Data Format Conventions

Date/Time Format

  • Standard: ISO 8601 format (2026-01-21T14:35:40Z)
  • Timezone: UTC timestamps
  • Relative time: Confirm if backend provides relative strings (e.g., "2h ago") or frontend calculates

Data Type Standards

  • Boolean: true/false (not 1/0)
  • Null handling: Use null for missing optional fields
  • Empty arrays: Return [], not null
  • Enum values: String format (e.g., "liked", "following")

13. Pagination Standards

Request Parameters

  • page (number, 1-indexed, default: 1)
  • limit or per_page (number, default: 20, max: 50)

Response Metadata

{
  "pagination": {
    "currentPage": 1,
    "totalPages": 10,
    "totalItems": 200,
    "perPage": 20,
    "hasNext": true,
    "hasPrevious": false
  }
}

15. Additional Questions for Backend Team

  1. Authentication:
    • What is the exact token refresh flow?
    • How should the app handle token expiration during active use?
    • Are there any IP-based restrictions or device limits?
  2. File Uploads:
    • Should we use direct upload or pre-signed URLs?
    • Are there automatic image optimizations (compression, resizing)?
    • What CDN is used for serving uploaded files?
  3. Real-time Features:
    • Are WebSockets available for real-time notifications?

    • What are the recommended caching strategies?
